# Support

ProdKit Storage is an open-source storage foundation, not a managed database service and not a hosted support product.

## Where to ask

Use GitHub issues when you have:

- a reproducible bug in ProdKit Storage;
- a documentation problem;
- a compatibility regression;
- a concrete reusable feature request that belongs in the storage foundation.

Use the repository's issue forms so the environment, version, reproduction steps, and operational impact are captured consistently.

Before opening an issue, check the README, `docs/`, existing issues, and the current release notes.

## What to include

Provide the ProdKit Storage version, Python version, PostgreSQL/PostGIS or Redis versions when relevant, minimal reproduction steps, expected and actual behavior, and sanitized logs or tracebacks.

Never include passwords, connection strings with credentials, API keys, private keys, customer data, or other secrets.

## Security

Do not report vulnerabilities through a public support issue. Follow [SECURITY.md](SECURITY.md).

## Deployment responsibility

Questions about a specific provider's HA topology, private networking, PITR retention, compliance posture, capacity planning, or incident process may require guidance from that provider or from the team operating the deployment. The repository can document integration contracts and safe defaults, but it cannot certify an individual deployment as production-ready.

No response-time or resolution SLA is implied for community support.
